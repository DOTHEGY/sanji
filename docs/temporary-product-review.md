# 임시 상품 검토: 작업자용 로컬 준비

이 경로는 실행 중인 브라우저 메모리에서만 검토합니다. 상품 원자료와 공식 출처를 검증했다는 뜻이 아니며, 실제 자료는 이 예시에 포함하지 않습니다. 도구는 로컬 JSON 전체를 프로세스 메모리에서 파싱하므로 신뢰할 수 있는 기기에서 실행하세요. inspect 출력은 원천명을 포함할 수 있어 작업자 전용으로 민감하게 취급합니다. build가 만드는 브라우저용 투영은 원천명, 원문 설명, 수수료, 선정·가격 조건, 출처 URL을 포함하지 않고 별도 작성한 표시명만 포함합니다.

1. 작업자가 상품 자료 배열 두 파일을 로컬에서 직접 확인합니다. `node scripts/prepare-transient-product-projection.cjs inspect <자료1.json> <자료2.json> > <검토용-투영.json>`은 안전 필터를 통과한 명칭과 1부터 시작하는 행 번호만 출력합니다. 명칭이 미확인이면 null입니다. 이 출력도 사적인 자료이므로 안전하게 보관하고 더는 필요하지 않으면 일반적인 사용자 통제 아래 처리하세요.
2. 원자료와 공식 상품 원문을 직접 대조하여 37개 그룹을 정합니다. 별도 매핑 JSON은 `confirmed`를 true로 두고 `mapping`에 정확히 37개 항목을 둡니다. 각 항목은 `rows`에 1부터 시작하는 원자료 행 번호들을, `representative`에 그중 대표 행 번호를 둡니다. 모든 원자료 행은 빠짐없이 정확히 한 번 사용합니다. 각 상품의 외부용 표시명은 내부 가격·할인·수수료·선정 조건을 빼고 작업자가 별도 작성한 displayName과 displayNameReviewed: true로 명시하며, 직접 대조하지 않았다면 두 필드를 생략합니다. 원천명은 표시명에 자동 복사되지 않습니다. 그룹의 중복·옵션 관계는 사람의 판단이며 자동 병합하지 않습니다. 예: `{"confirmed":true,"mapping":[{"rows":[1,2],"representative":1},...]}`에서 생략 부호는 예시이며 실제 JSON에는 37개 항목이 필요합니다.
3. `node scripts/prepare-transient-product-projection.cjs build <자료1.json> <자료2.json> <매핑.json> > <브라우저용-투영.json>`을 실행합니다. 유효하지 않은 매핑은 결과를 출력하지 않습니다. JSON 원문에 원천명, `fee`, 설명, 선정 조건, URL 등의 값이 있더라도 투영 결과로 내보내지 않습니다. 명칭 필터는 모든 민감한 표현을 보증하지 못하므로 작업자가 투영을 반드시 확인해야 합니다.
4. 검토 화면에서 브라우저용 투영만 로컬로 선택합니다. 작업자는 상품마다 공개 공식 출처, 관측 시각, 직접 대조한 정형 사실 및 진행 가능 여부를 입력하고, 제공 형태를 미확인·단품·정기형으로 명시합니다. 단품은 이용·판매 기한 등 중요한 제한이 없다고 확인된 경우에만 지원하며 제한이 있거나 불명확하면 보류합니다. 정기형은 반복 결제, 계약 기간, 배송·결제 주기, 갱신 여부, 취소·의무 등 중요한 조건 전체를 원문 대조해야 합니다. 현재는 언제든 취소 가능하고 별도 의무가 없는 것으로 확인된 경우만 지원하며 그 조건을 초안에 함께 표시합니다. 그 밖의 취소·의무 조건은 자동으로 단순화하지 않고 별도 확인으로 남깁니다. 하나라도 불확실하면 제외합니다. 조건을 숨겨 단품처럼 표시하지 않습니다. 이어서  해당 대화의 Instagram 원문·관심·거절/유료 조건을 직접 확인합니다. 출처와 판단은 자기기재이며 자동 진위 판정이 아닙니다. 자료나 원문이 불명확하면 제안하지 않습니다. 미검토 항목이 있으면 37개 입력 형식도 전체 상품의 검증이나 추천 최적성을 보증하지 않습니다.
5. 편집란 삽입은 별도 확인을 요구하고 기존 문구를 대체합니다. 삽입만으로 저장·발송하지 않습니다. 기존 검수는 다시 확인해야 하며, 일반 초안 저장은 엄격 검수 저장이 아닙니다. 최종 사용자가 원문, 상대방, 내용, 숨겨진 비용 표현을 재확인하세요.
