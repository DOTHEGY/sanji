# 일일 크리에이터 후보 준비 모듈

전체 캠페인 구현·활성화 조건은 [운영 가이드](CREATOR-DAILY-CAMPAIGN-OPERATIONS.md), 화면은 [관리 화면](YOUTUBE-DAILY-PREPARATION.md)을 기준으로 봅니다. 이 문서는 전체 시스템 안에서 발송 권한을 만들지 않는 선별·준비 계층을 설명합니다. 운영 배포, 실제 반복 실행, 실제 메일 발송은 하지 않았습니다.

## 선별과 중복

- 하루 YouTube 50명과 기존 Instagram DB 10명은 목표 상한이며 보장 수량이 아닙니다.
- 구독자/팔로워 30,000~500,000 포함 범위. 최근 활동은 잠정 90일 이내입니다.
- 원문, 관측 시각, 먹방·활동·업무 연락처 근거가 필요합니다. 단순 페이지 조회일을 수치 관측일로 승격하지 않습니다.
- 외모나 이름에서 성별을 추정하지 않습니다. 조건 미달 후보로 목표를 채우지 않습니다.
- 공개 이메일은 업무 용도 원문과 크리에이터 소속을 확인합니다. 공개 주소가 수신 동의나 법적 분류를 대신하지 않습니다. 최신 삭제·모호한 주소 관측이 이전 주소보다 우선합니다.
- YouTube 식별자 대소문자를 보존합니다. 플랫폼 식별자와 이메일을 함께 비교하고 Gmail 점/플러스/googlemail 별칭도 중복 처리합니다. 별개 플랫폼의 동일 인물 여부가 확인되지 않으면 임의로 합치지 않습니다.
- 전체 Sanji 이력 읽기가 불완전하면 중단합니다. 준비 시 저장 이력을, 별도 발송기에서 Gmail 실시간 이력을 확인합니다.
- 부분적인 같은 날짜 목록은 새 검토를 명시적으로 준비할 때 남은 50/10 한도까지만 추가할 수 있습니다. SQL 계정 잠금과 고유 제약으로 다시 확인합니다. 결과 불명 POST는 재전송하지 않고 상태를 확인합니다.

## 구성과 경로

- `domain.mjs`: 근거 검증, 선별, 정규화, 고정 문안 치환.
- `service.mjs`: 순수 준비 서비스와 호환 준비 전용 handler. 송신 기능이 없습니다.
- `repository.mjs`: 원본과 전체 저장 이력을 읽고 계정별 원장을 저장합니다. 원본을 읽은 시점의 버전을 전달합니다.
- `campaign-controller.mjs`, `campaign-runtime.mjs`: 전체 인증 API와 분리된 탐색/준비/발송 조립.
- `index.ts`: 현재 전체 캠페인 API entrypoint입니다. `/send` 공개 경로는 없습니다.
- `supabase/pending/creator-daily-outreach.sql`: 선별 원장만 정의합니다. 별도 공급·연락처·캠페인 SQL과 함께 승인된 순서로 적용해야 하며 빌드가 자동 적용하지 않습니다.

`/collect`는 일일 탐색, `/prepare`는 완료된 탐색과 검토된 원본의 준비입니다. 둘은 빈 JSON 요청만 받으며 인증된 소유자를 서버에서 결정합니다. 수신자·문안을 이 경로로 지정할 수 없습니다. 비공개 설정·개별 근거 검토·예약 정책 경로는 전체 컨트롤러에 별도로 정의되어 있습니다.

## 근거 출처

기존 YouTube 수동 기록의 연락처 참고자료를 자동 승인하지 않습니다. 신규 공식 API 사실은 별도 29일 캐시이며 독립적으로 검토한 이름/식별자/먹방/연락처 증거와 분리합니다. 준비에 복사된 API 사실도 실제 삭제합니다.

Instagram은 기존 `sanji_creator_recovery`만 사용합니다. 원본 상태·제외·소속 확인을 유지하고 추가 검토는 별도 계정/원본 버전 결합 테이블에 저장합니다. 만료나 빈 새 연락처가 이전 연락처를 되살리지 않도록 최소 검토 표식을 보존합니다. 새로운 Instagram 크리에이터를 가져오지 않습니다.

## 고정 문안과 본문 사진

승인 제목·본문의 `[채널명]`만 실제 검토된 이름으로 대체합니다. 금액, 사실, 약속, 인사말을 임의로 바꾸지 않습니다. 사용자가 쓴 “첨부한” 문구도 그대로 둡니다.

승인된 두 원본 사진은 CID 인라인 방식으로 서명 바로 위에 표시합니다. 일반 첨부나 공개 제품 이미지 URL을 만들지 않습니다. 파일 순서·해시·크기·PNG 구조와 실제 압축 픽셀을 검증합니다. 기존 Gmail 서명을 정확히 한 번 사용하며 현재 계정과 저장 설정을 다시 확인합니다. 서명의 기존 원격 로고는 유지할 수 있습니다. 일부 메일 앱의 인라인 파일 표시 형태까지 보장하지는 않습니다.

전체 캠페인은 문안·원본 사진·서명을 비공개 불변 설정으로 저장하도록 구현되었습니다. 두 빵의 이름과 함께 승인된 사진을 묶는 캠페인 자산 모드가 있으며, 관련 없는 상품 DB 레코드나 사진별 제품명을 추정하지 않습니다. 실제 사용자 자료는 공개 코드/빌드/테스트에 포함하지 않습니다.

## 검증과 남은 운영 단계

`npm run test:creator-daily-outreach`와 `npm run check:creator-daily-outreach`를 실행합니다. 모의 제공자, 로컬 PostgreSQL, 합성 이미지 검증이며 실제 발송을 하지 않습니다. 원본 두 PNG와 정확한 서명/본문은 별도의 비공개 로컬 MIME로 검증했습니다.

운영 승인과 schema drift/advisors 확인, 실제 런타임·브라우저·현재 API 쿼터 확인, 근거/수신 대상 분류, 공식 반복 작업과 보존 작업 설정·검증이 남아 있습니다. 반복 작업이 연결되었다고 설정 플래그만 보고 주장하지 않습니다. 자세한 적용 순서와 한계는 운영 가이드에 있습니다.
