# 크리에이터 복구·발굴 운영 반영 계획

## 순서와 데이터

1. 기존 복구 자료 13,932행을 전용 테이블에 안전하게 가져옵니다. 테스트 계정 6개는 제외했고, Instagram 링크가 없는 282행은 링크 확인 대기로 보존합니다. 원본의 소개란·출처·0과 결측값을 유지합니다. 소개란에 적힌 이메일을 추출한 2,887개 계정과 공유 이메일 관계 54개도 남깁니다. 현재 유효성은 미검증입니다.
2. Instagram 공식 API를 우선합니다. Facebook 로그인 방식 앱·프로페셔널 계정·권한이 연결되면 공식 해시태그 최근 미디어에서 사용자명이 제공된 계정을 최대 20건씩 가져올 수 있도록 준비했습니다. 일반 개인 계정 전체 검색·이메일 제공을 가정하지 않습니다. 이미 아는 프로페셔널 계정의 팔로워를 개별 조회하는 코드도 준비했습니다.
3. 공식 API가 부족한 경우에만 TAGby가 제공하는 정상 목록 UI 및 기존 유사 추천 결과 XLSX를 보완 자료로 씁니다. 숨은 API를 호출하거나 제한을 우회하지 않습니다. TAGby 사용·저장 및 자동화 조건은 아직 확인되지 않았습니다. 저장 자체가 금지라면 수집하지 않습니다.

한국어·주제·공구/협업 표현은 우선순위 근거입니다. 구독자 수·이메일이나 공구 이력이 없다는 이유만으로 후보를 탈락시키지 않습니다. 현재 규칙 기준으로 우선 1,146건, 탐색 12,239건, 링크·계정 유형 검토 547건이며 한국 국적·현재 활동·공구 적합성이나 정확한 개인 계정 유형을 확정한 결과가 아닙니다. 질병 등 민감 속성은 추정하지 않습니다. 추천 시 탐색 비율은 기본 20%로 설정할 수 있습니다.

## 구현 및 검증 범위

- 별도 소유자별 후보·추천·근거·설정·제공자 제한·전달 묶음 테이블. 기존 브랜드·발송 데이터는 수정하지 않습니다. 동일 아이디는 합치되 기존 DB, Meta 게시물, TAGby 일반 목록과 유사 결과의 제공자·종류·기준 아이디·유사도·묶음·관찰시각을 따로 보존합니다.
- 한국시간 N명 목표·실행 시각, 기록하지 않는 미리보기, 수동 추천 확정, 이미 추천한 계정 제외, 보류·제외·연락 완료, 날짜별 목록, 아이디 복사·CSV·이메일 필터. 자동 추천은 기본 꺼짐이며 별도로 켜기 전 실행하지 않습니다.
- Meta: 별도의 `META_FB_APP_ID`, `META_FB_APP_SECRET`, 기존 `TOKEN_ENCRYPTION_KEY`가 서버에 있어야 합니다. Meta 앱의 Facebook 로그인 리디렉션에 `https://ofasbfpeapbdcotnptvz.supabase.co/functions/v1/bright-function/creator-meta/callback`을 등록해야 합니다. `instagram_basic`, `instagram_manage_insights`, `pages_show_list`, `pages_read_engagement`와 해시태그 검색용 Instagram Public Content Access 기능 및 필요한 App Review를 확인해야 합니다. 토큰은 서버 AES-GCM 암호화 저장 방식이며 화면·로그·CSV에 노출하지 않습니다. 공식 OAuth와 실제 API 권한은 아직 실측하지 않았습니다.
- Meta 해시태그 조회는 명시적으로 실행할 때만 동작하며 기본 일일 한도 0, 요청당 최대 20건, 7일 고유 해시태그 30개 제한을 적용합니다. 최근 24시간 공개 미디어만 대상이며 사용자명이 제공되지 않으면 후보를 만들지 않습니다. 결과의 한국인·공구 적합성은 불확실하다고 표시합니다. 추정 이메일은 생성하지 않습니다. 보유 계정 조회는 동일한 일일 조회 한도에 포함하며 실패하면 기존 데이터는 보존합니다.
- TAGby의 검색·목록 열람은 dot의 인증된 브라우저에서 수행하고 산지는 결과만 받습니다. 브라우저 로그인 세션·쿠키를 산지에 복제하지 않으며 별도 PC 워커나 서버가 필요하지 않습니다. 확인된 결과는 기존 산지 관리자 인증을 사용하는 CSV/JSON 가져오기 경로로 한 번에 최대 30개씩 전달합니다. 사용자가 로그인한 두 환경 사이의 실제 전달은 운영 배포 후 검증해야 합니다. TAGby 자동화·저장 조건이 금지한다면 우회하지 않습니다.
- 유사계정 XLSX 어댑터는 확인된 6개 열 `유사도/SNS ID/SNS URL/평균 좋아요/평균 댓글/팔로워`를 지원합니다. 이메일·소개란은 없는 것으로 처리하며 유사도를 공구 적합성으로 해석하지 않습니다. 실제 파일은 다른 브라우저에서 확인됐고 이 환경은 모의 XLSX만 시험했습니다. 새 유사 검색이나 3회 무료 한도를 자동 사용하지 않습니다.
- 신규 외부 수집과 갱신은 자동 실행되지 않습니다. 조회 제한·비용 상한 설정은 외부 유료 서비스 결제를 승인하거나 실행하지 않습니다. 매일 전체 DB에 AI를 호출하지 않으며 이메일·DM 자동 발송 기능을 만들지 않습니다.

## 비운영 시험

- 복구 CSV 전체를 시험 DB에 13,932건 저장하고 다시 가져와 중복 0건을 확인했습니다. 282건 링크 미확인과 2,887건 이메일 보존, 첫날·다음 날 반복 추천 방지를 검증했습니다.
- 브라우저 픽스처에서 이메일 있음/없음, 링크 확인 대기, 복사·CSV 및 설정 화면을 확인했습니다. 실제 로그인된 Meta·TAGby 화면은 확인하지 못했습니다.
- Meta OAuth state, 요청 한도, 프로필 오류, TAGby 정상 열람 결과 전달·응답 불명 후 재전송·XLSX 형식 등은 모의 시험입니다.

## 운영 반영 승인 범위

1. 현재 Edge 함수·DB 상태 백업 후 새 마이그레이션을 적용합니다. 새 테이블·함수와 크리에이터 전용 설정만 추가합니다.
2. 복구 자료 13,932행을 100행 배치로 전용 테이블에 적재하고 재실행 중복·출처·이메일·상태를 검증합니다. 기존 행은 덮어쓰지 않습니다.
3. Edge Function 및 GitHub Pages UI를 배포합니다. 기존 브랜드·메일·발송 설정과 예약을 유지하고, 자동 추천·외부 조회 한도는 기본 0/꺼짐으로 둡니다. 이전 Apify 자동 실행은 연결하지 않습니다.
4. 자동 추천 활성화, 실제 Meta 앱 설정·인증, dot의 태그바이 접속·매일 실행, 새 유료 사용은 각각 추가 확인 후 진행합니다. 새 대량 수집이나 구독 변경은 포함하지 않습니다.

복구: Edge 함수와 UI를 이전 버전으로 되돌리고 추천 설정을 끌 수 있습니다. 신규 테이블은 백업 후 별도 삭제 승인 없이는 보존합니다.

## 태그바이 비용 판단

사용자가 언급한 월 7만원 기준으로, 기존 우선 후보 1,146건은 하루 30건 단순 산술상 최대 약 38일 분량입니다. 넓게 보존한 탐색 12,239건은 국적·활동·개인 계정 여부를 추가로 확인해야 하므로 검증된 영업 대상 12,239명이라는 의미가 아닙니다. Meta는 이미 아는 프로페셔널 계정과 제한된 해시태그 검색에 사용할 수 있지만 전체 크리에이터를 검색하거나 이메일을 제공한다고 가정하지 않습니다. Meta 앱 등록·권한·검수 여부와 Supabase 사용량에 따라 비용·노력이 달라질 수 있습니다.

태그바이의 일 3회 무료 유사 검색 및 최대 30개 결과와 XLSX 6열은 사용자가 다른 브라우저에서 확인한 사항이며 이 환경은 직접 확인하지 못했습니다. 3×30은 최대 90개 결과이지 신규 고유 후보 90명을 보장하지 않습니다. 공식 API와 기존 DB로 충분한지, 유료 플랜에서 중복을 뺀 유효 신규 후보가 월 7만원의 가치가 있는지 소량 대조 후 판단합니다. 이미 저장된 데이터의 해지 후 사용 조건도 미확인입니다. 구독 변경이나 과금 실행은 하지 않습니다.

참고 Meta 문서: https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery/ 및 https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-hashtag/recent-media/ (2026-10-27 확인).

## dot가 정상 열람한 결과 전달 및 API 선택

- 기본 전달 방식은 산지 관리자 로그인 세션으로 `creator-recovery/import-visible`에 최대 30개씩 보내는 것입니다. 새로운 지속 자격증명은 필요하지 않으며 TAGby의 쿠키·세션은 산지에 보내지 않습니다. CSV·JSON 파일 입력 UI도 준비했습니다. GPT가 기존 완료 유사 추천에서 전송하는 경우 기준 아이디를 입력할 수 있으며, 해당 메모는 유사도와 공구 성과를 동일시하지 않습니다. 요청 묶음은 트랜잭션·내용 해시로 저장해 재전송 시 중복을 피합니다. 기존 후보의 bio·메일·팔로워를 덮어쓰지 않고 출처별 근거를 별도 보관합니다.
- 다른 환경에서 받은 TAGby 유사 추천 30행 샘플은 SHA-256 `485a674849dab2189d6d930c3d35deb7f066dbe263d8337144aa99b0c2e59139`로 대조했습니다. 13,932행 시험 DB에 더했을 때 교집합 6건, 신규 24건, 기존 핵심 데이터 갱신 0건, 새 출처 근거 30건, 재전송 신규 0건이었습니다. 원본 순서·아이디·URL·팔로워를 보존하며 시간은 파일 확인 시각입니다.
- dot가 공개 소개란을 읽고 이메일이 없었다고 보고한 3개 계정의 결과는 `email_not_in_bio`라는 **시각 미제공 관찰**로 시험 DB에서 보존했습니다. 실제 소개란 원문·정확한 시각은 전달되지 않아 만들어 넣지 않았습니다. `bio_unreadable`, `not_checked`, `email_present`를 구분하고 실패 시 기존 값을 지우지 않습니다.
- 대안으로 YouTube Data API는 공개 채널 검색과 채널 설명을 제공하지만 Instagram 목록이나 이메일을 보장하지 않습니다. 2026-10-27 Google 문서의 기본 할당은 `search.list` 일 100회와 다른 엔드포인트 합산 10,000 단위로 별도 표시되어 있습니다. 실제 프로젝트 할당·결제 여부·정책은 계정별로 확인해야 합니다. 신규 계정·API 키를 만들거나 호출하지 않았습니다. https://developers.google.com/youtube/v3/determine_quota_cost
- Instagram 공식 API 외 크롤링 API는 사용자가 공급자를 선택하기 전 가입·연결·실행하지 않습니다. Apify 자동 발굴은 연결하지 않습니다. 직접 브라우저 조회는 제한 없는 무로그인 보장이 아니며, TAGby의 사용·저장 조건을 우회하지 않습니다.
