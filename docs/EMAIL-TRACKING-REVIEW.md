# 이메일 열람 추정 · 간소형 검토안

상태: **로컬 구현·테스트 완료, 운영 미배포, 실제 추적 비활성, 실제 테스트 메일 미발송**.

## 적용 범위와 선택

- 현재 작업 환경에서 확인한 Git 저장소는 `sanji` 하나다. 운영 중인 Supabase Edge Function + Gmail API의 브랜드·크리에이터 이메일 작성/회신/승인 발송 경로에 연결했다.
- 다른 B2B 콜드메일 프로젝트에는 접근·수정하지 않았다. 같은 저장소의 대체 Node/SQLite Render 백엔드는 이번 추적 구현 대상이 아니다. 그 경로에서는 추적 미연결로 표시하고 기존 발송을 유지한다.
- Instagram DM, 발굴 완료 운영 알림, 과거 발송에는 픽셀을 붙이지 않는다. 과거 메일을 다시 보내지 않는다. 자동 발송 설정·빈도·재시도·재발송 조건을 변경하지 않는다.
- Google 공식 `users.messages.send` 및 push notification 문서를 확인했다. Gmail 발송/메일함 변경 알림은 수신자의 열람 웹훅이 아니다. Mailsuite의 브라우저 확장 프로그램이나 외부 API를 연결하지 않았으며 외부 업체의 추적 이벤트를 수집한다고 표시하지 않는다.

| 선택지 | 비용·안정성·개인정보 고려 | 결정 |
|---|---|---|
| Gmail 자체 열람 이벤트 | 해당 API 기능 없음. 메일함 UNREAD 라벨은 수신자의 열람 상태가 아님 | 사용 불가 |
| 별도 추적 업체/Mailsuite API | 서비스별 API·계약·요금·웹훅 검증 필요. 별도 사업자에 추가 정보를 전달할 수 있음. 현재 연결·지원 여부 미검증 | 이번에는 연결하지 않음 |
| 기존 Supabase의 직접 픽셀 | 추가 도메인·DNS·OAuth scope·고정 외부 구독 불필요. Edge 요청과 DB 사용량 증가. 이벤트·토큰 보관을 직접 제한할 수 있음 | 기본 선택, 승인 전 꺼짐 |

## 동작과 한계

실제 승인된 이메일을 예약한 뒤에만 32바이트 암호학적 난수 토큰을 생성한다. URL에는 토큰만 들어간다. 서버에는 토큰 원문 대신 SHA-256 해시와 발송 건 연결을 저장한다. 후속 메일은 별도 토큰이다. 서로 다른 단독 수신 메일은 토큰을 공유하지 않는다.

기존 다중 To 발송은 수신자를 나눠 재발송하지 않는다. 한 통에 여러 주소를 넣는 경우 하나의 공용 본문 픽셀을 쓰고 **개인별 구분 불가**로 표시한다. 수신자별로 구분하려면 기존 승인 과정에서 각 수신자를 별도 이메일 발송 건으로 선택해야 한다. 승인 없이 발송 통수를 늘리지 않는다.

픽셀 경로는 기존 HTTPS Edge 주소 아래 `/email-events/pixel/<token>.gif`다. 실제 GIF89a 1×1 투명 이미지를 반환한다. 미등록·만료 토큰이나 DB 장애에도 수신자 정보 없이 같은 이미지를 반환한다. HEAD·미리보기는 이벤트를 만들지 않는다. 이미지 요청만으로 회사 영업 상태나 발송 상태를 바꾸지 않는다.

순수 텍스트 원문을 그대로 유지한 `multipart/alternative` HTML 표현을 추가하며 HTML에서 사용자 카피를 이스케이프한다. 제목·서명·원문 링크·첨부·답장 Message-ID/References를 보존한다. HTML의 링크는 추적 리다이렉트로 바꾸지 않는다. 추적 설정 오류·저장 장애에는 픽셀 없이 기존 승인 메일을 한 번 보내는 경로로 진행한다.

Gmail 보낸편지함, 전달본, 보안 제품에서 같은 픽셀을 요청한 주체를 픽셀만으로 정확히 구분할 수 없다. 앱 미리보기/상세에는 픽셀을 렌더링하지 않으며 관리자 자기앞 발송과 명시한 내부 테스트는 지표에서 제외한다. **외부 Gmail 보낸편지함 열람을 완벽히 걸러낸다고 보장하지 않는다.** Apple Mail 실제 환경의 프리로드·캐시·차단도 사람의 열람 판정으로 사용하지 않는다.

Google 이미지 프록시·사전 요청 헤더·일부 스캐너 User-Agent 패턴은 메모리에서만 확인한 뒤 `자동 요청 의심 · 자체 추정` 사유 코드만 저장한다. Google 이미지 프록시가 실제 사람이 여는 과정에서도 사용될 수 있으므로 자동 여부를 확정하지 않는다. AppleWebKit 문자열만으로 자동 요청이라고 분류하지 않는다. 제공자 분류 웹훅을 사용하지 않으므로 웹훅 서명/중복 수신 테스트는 이번 방식에 해당하지 않는다.

## 표시와 집계

- `열람 추정 / 감지 없음 / 추적 미적용`, 내부 테스트·보관 만료·중지는 별도 표시.
- 최초/마지막 **이미지 요청 시각**, **이미지 요청 횟수**. 읽은 시각·읽은 횟수로 표현하지 않음.
- Gmail 서버 접수·거절·발송 결과 미확인 및 동기화된 회신을 구분. **반송 감지는 이번 간소형에 추가하지 않았으며 반송은 미확인으로 표시**.
- 열람 추정률 = 선택한 발송일 기간의 `중복 제거한 추적 적용·Gmail 접수·보관 중인 비테스트 발송 건 중 감지 건 / 같은 조건의 발송 건`. 다중 To도 발송 한 건. 과거 미적용·테스트·만료는 분모에서 제외. 자동 요청 의심 포함 여부 선택.
- 발송일 기간 코호트에 대해 보관 중인 이후 이미지 요청을 현재 기준 반영. 보관 기간 밖의 과거 이벤트를 복원하거나 0회로 간주하지 않음.
- 사람 회신율·긍정 회신율을 먼저 표시. 분모는 기간 내 접수된 고유 대상, 분자는 연결 대화의 사람 회신 대상. 자동 응답 제외. 긍정 여부는 사용자 대화 분류 기준. 직접 In-Reply-To가 없는 회신은 특정 메일의 직접 회신으로 확정하지 않음.
- 열람·감지 없음은 후속 메일을 시작하는 조건으로 연결하지 않음.

## 고지·선택·보관

공개된 이메일 주소라는 사실을 추적 동의나 적법한 처리 근거로 취급하지 않는다. 캠페인에 처리 근거 검토 기록과 고지 문구/정책 링크를 입력하고, 사용자 작성 본문에 그 고지가 실제 포함돼 있는지 검사한다. 사용자 카피에 임의로 고지를 추가하지 않는다. 입력한 검토 기록은 실제 고지·동의 절차나 법률 검토를 대신하지 않는다. 개인정보보호법상 처리 근거·고지·동의/처리정지, 플랫폼 정책·국외 처리 조건은 운영자가 적용 대상에 맞게 검토해야 한다. **국내 최신 유권해석을 확인·법적 적합성을 확정한 것은 아니며 실제 수신자 활성화 전 미확인 사항**이다.

수집: 발송 건의 난수 토큰 해시, 서버 연결 키, 이미지 요청 시각, 최소 의심 사유 코드. 앱은 IP·정확한 위치·원본 User-Agent·쿠키·기기 식별자를 저장하지 않는다. Supabase 인프라 자체의 접속 로그/백업 처리는 사업자 정책과 프로젝트 로그 보관 설정을 별도로 확인해야 한다. 이 앱의 최소화 설정이 인프라 로그까지 없다는 뜻은 아니다.

기본 보관은 발송부터 30일(7~90일 선택). 기존 메시지의 보관 기간은 발송 시 설정을 유지한다. 기존 승인 실행기의 정리 작업이 만료 토큰 연결과 이벤트를 삭제한다. 만료된 픽셀은 같은 이미지로 응답하고 새 이벤트를 저장하지 않는다. 남는 영업 발송 기록의 보관은 기존 업무 자료 정책과 별개다. 악용 방지를 위해 발송 건·UTC 날짜당 최대 1,000개의 이미지 요청 이벤트만 기록한다.

서비스/캠페인 off는 기존 픽셀의 신규 수집도 중단한다. 처리정지·삭제 요청을 받으면 소유자는 메일 상세에서 **이 발송건 추적 중지·이벤트 삭제**를 실행할 수 있다. 통계·설정·삭제는 관리자 인증 뒤에서만 접근하며 공개 이미지 주소로는 개인·회사·캠페인 정보를 조회할 수 없다.

## 배포·활성화 계획 — 아직 실행하지 않음

1. 승인 후 마이그레이션 `202610220006_email_tracking.sql`, 기존 Edge Function 코드, UI와 검토된 정책 페이지를 배포한다. 새 테이블은 서비스/캠페인 기본 off. 기존 데이터는 추적 미적용이며 기존 승인 미리보기에는 추적을 소급 추가하지 않는다.
2. `EMAIL_TRACKING_ACTIVATION_APPROVED`는 기본 미설정/off다. 별도로 확인받기 전 true로 바꾸지 않는다. `EMAIL_TRACKING_TEST_ONLY`도 기본 true이며 이 모드에서는 관리자 로그인 이메일 또는 연결 Gmail 자기앞 수신자만 등록 가능하다. 회사/크리에이터 실제 수신자 추적은 허용되지 않는다.
3. 아래 테스트 메일의 대상·내용 승인을 받은 뒤에만 테스트 캠페인과 자기앞 테스트 한 통을 승인 발송한다. 정상 이미지·반복 요청·차단·내부 지표 분리 확인. 회사 영업 예약을 재개하거나 수신자·양을 늘리지 않는다.
4. 실제 수신자 대상 추적은 고지 문구·처리 근거·범위를 확정해 **별도로 승인**받은 뒤에만 test-only 제한을 해제한다. 필요하지 않으면 계속 off로 유지한다.

### 복구 방법

즉시 수집을 멈추려면 서버 활성화 플래그를 false 또는 서비스/캠페인 설정을 off로 바꾼다. 필요하면 개별 연결을 삭제한다. Gmail 발송을 재시도하거나 과거 메일을 다시 보내지 않는다. 기존 이메일의 이미지가 깨지지 않게 비수집 GIF 경로는 마지막 보관 기간이 끝날 때까지 유지한다. 코드 롤백 시 신규 추적 준비만 끄고 이 무해한 이미지 응답 경로는 유지하는 방식이 권장된다.

### 비용·권한

추가 도메인/DNS/외부 계정/유료 추적 서비스는 필요 없다. 기존 Gmail send 권한과 기존 Supabase DB·Edge 배포 권한을 사용한다. 예시로 하루 40통·통당 이미지 요청 3회면 월 약 3,600회의 이미지 Edge 요청과 이벤트, 약 1,200개의 발송 토큰 연결이 생긴다. 실제 청구액은 프로젝트 요금제·기존 사용량·프록시 요청 횟수에 따라 달라지므로 **추가 비용 0원으로 확정하지 않으며 청구 확인은 미실시**다. 대량 요청·보안 자동 로딩으로 더 증가할 수 있다.

## 검증 범위

`tests/email-tracking.test.cjs`는 실제 로컬 PostgreSQL 엔진(PGlite), MIME 디코딩, 브라우저로 검증한다. 실제 Gmail 전송/수신, Gmail·Apple Mail·Outlook의 외부 이미지 동작, 실제 전달·이미지 차단 설정, 보안 게이트웨이·캐시는 미검증이다. 웹훅은 사용하지 않는다. 서버/DB 장애는 모의 장애이며 실제 Supabase 장애를 유발하지 않았다. 운영 배포, 실제 픽셀 요청, 실제 수신함 시험을 완료했다고 주장하지 않는다.

## 2026-10-23 운영자 명시적 활성화 요청

사용자가 “지금 도대체 켜줘. 회신도 왔던데 …”라고 지시하여 신규 승인 이메일에 한해 활성화한다. 기존 발송·예약 본문과 발송량을 변경하거나 재발송하지 않는다. 새 초안에는 추적 고지를 서명 뒤에 붙이고 미리보기에도 표시한다. 서비스·캠페인·개별 발송에서 해제 가능. 앱의 이미지 이벤트는 30일 보관하며 IP·원본 UA를 보관하지 않는다. 공용 본문을 여러 주소에 보내면 개별 수신자를 구분하지 않는다. 과거 메일은 추적 미적용으로 유지한다.

회신 동기화는 기존 Gmail 대화 ID를 25개씩 순환 조회하고 화면의 상태도 갱신한다. 자동 응답·반송은 사람 회신으로 세지 않는다. Gmail 읽기·DB 동기화만 실행하며 발송 API는 호출하지 않는다. 오발송 방지 감사의 소스·대기열 정리 변경은 별도 검토본이며 이 활성화 배포에 포함하지 않는다.

복구: 서비스 추적 끄기 또는 EMAIL_TRACKING_ACTIVATION_APPROVED=false. 신규·기존 픽셀 이벤트 수집 중지. Gmail 자동 동기화 중지는 cron sanji-gmail-reply-sync 비활성화. 메일 발송·수신 이력은 삭제하지 않는다.
