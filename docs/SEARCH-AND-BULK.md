# 검색 보충과 일괄 이메일

자동 발굴은 한국시간 자정의 기업·협회 목록 갱신과 별도로, 대기 후보가 8곳 미만이면 공개 검색어를 보충한다. Google, 네이버, Bing RSS, DuckDuckGo를 순환하며 결과가 비었거나 제한되면 다음 제공자를 확인한다. 계정·유료 API 키는 사용하지 않는다. 보안 확인이나 로그인·차단을 우회하지 않는다. 제공자 HTML 변경이나 데이터센터 차단으로 결과가 없을 수 있으며 하루 40개 업체 확보를 보장하지 않는다.

검색어 2개 단위로 15분 간격, 하루 최대 64개 검색어를 확인한다. 하나의 검색어는 최대 4개 제공자를 시도한다. SQL lease로 중복 실행을 막고, 이메일 확보 목표를 달성하면 보충을 중단한다. 검색 제목은 업체 후보이며 소유 법인이나 식품 분류의 검증 결과가 아니다. 출처·검색어·원본 링크를 비공개 DB에 저장한다. 검색 결과에 적힌 이메일은 자동 채택하지 않고 홈페이지·공식 연결몰에서 다시 확인한다. 회사명·도메인·기존 이메일 중복을 검사한다. 진행 화면에 제공자별 성공·실패와 후보 추가 수를 표시한다.

브랜드 이메일 화면의 `현재 목록 전체 선택` → `선택한 메일 일괄 검토` → 소유 관계 확인·발송 근거 입력 → `최종 발송 내용 확인` → 일괄 승인 → `승인한 메일 지금 일괄 전송`으로 진행한다. 회사 확인 보류 대상은 전체 선택에서 제외한다. 각 회사에는 해당 회사의 허용된 이메일들을 수신자로 묶어 한 통을 보낸다. 개별 체크와 예약 발송도 유지한다. 수신자·내용·첨부를 바꾸면 최종 승인은 무효가 된다. 발송은 승인된 서버 미리보기의 hash로 순차 요청하며 중복·수신 거부·템플릿 버전 검증을 그대로 적용한다. 오류는 건별로 표시하며 자동 재시도하지 않는다.

## 열람 상태

Gmail API의 `messages.send` 성공은 서버 접수이며 받은편지함 도착·읽음이 아니다. Gmail API는 일반 수신자의 열람 여부를 제공하지 않는다. 현재 산지는 Mailsuite와 연동하지 않았으며 Gmail 브라우저 확장 프로그램이 API 발송 메일에도 추적을 넣는다고 가정하지 않는다. Mailsuite에서 별도로 추적한 메일은 해당 제품에서 확인해야 한다. 추적 이미지 요청 이벤트도 보안 스캐너·이미지 프록시·이미지 차단의 영향을 받으므로 사람의 실제 열람으로 확정할 수 없다. 현재 산지는 추적 이미지를 삽입하거나 열람 수치를 생성하지 않는다.

배포 시 `202610220003_search_refill.sql` 적용 후 Edge Function을 업데이트한다. 공개 설치용 SQL은 `public/setup/search-refill.sql`이다. 검색 자체에는 유료 검색·AI 호출이 없지만 Supabase 실행·DB 사용료와 Gmail 계정의 제공자 할당량은 별개다.

## 실행 상태·자동 조사

상단 실행 상태판은 30초마다 새로 읽는다. 실제 Edge 실행 시작·종료 기록, 수집 lease와 검색 lease를 구분해 검색 중/홈페이지 확인 중/제품·회사 조사 중/정상 대기/설정 중단/실행 오류/실행 지연/예산 사용 완료/목표 달성을 표시한다. 5분 간격 실행을 예상하되 실제 수집 완료 시각을 보장하지 않는다. 마지막 실행이 12분 이상 없거나 시작한 작업이 3분 이상 미완료이면 지연으로 표시한다. 최초 배포 후 아직 실행 기록이 없으면 수집 중이라고 표시하지 않는다.

확보율 분모는 한국시간 오늘 홈페이지 확인 처리 횟수이며 재확인도 포함한다. 현재 저장된 업체 기록의 접속 실패·부분 오류·이메일 미발견 수는 누적 시도 횟수와 구분한다. 과거에 수집하지 않은 시도별 소요시간·오류 이력은 소급 생성하지 않는다. 새 수집 시도부터 오류·처리시간을 감사 기록에 남긴다. Supabase 실제 청구액은 이 화면에서 확인되지 않는다.

이메일 확보 뒤 공식 페이지의 구조화 상품 정보·상품명·상품 상세 제목으로 제품을 선정하고, 공개된 제품군만 확인되면 그 범위를 명시한다. 직접 확인한 이름과 콘텐츠 제작 제안으로 2문장 개인화를 자동 작성하며, 유료 AI 모델은 자동 호출하지 않는다. 기존 완성 개인화와 사용자가 저장한 공통 본문·제목·서명은 유지한다. 공식 페이지와 이메일 게시 원문을 대조하며, 같은 사이트라는 이유만으로 법적 분류·유통 권한을 확인됐다고 표시하지 않는다. 업체명·관계 근거가 맞지 않으면 공식 검색·원문 재확인을 수행하고 사유를 남긴다. 반복 조사에서도 제안 대상이 확인되지 않는 동명 업체는 정상 발송 목록에서 제외한다. 재조사 기록과 기존 연락처는 보존하며 자동 발송하지 않는다.

운영 상태 저장용 추가 마이그레이션: `202610220004_discovery_runtime.sql`.

## 매일 자정 시작·완료 메일

한국시간 00:00은 UTC 15:00이다. `sanji-daily-discovery`는 `0 15 * * *`, 후속 처리 실행기는 `*/5 * * * *`로 진행한다. 새 날짜의 카운터와 중복 제외 후보를 사용하며 목표가 채워지기 전에는 완료 알림을 보내지 않는다.

완료 알림은 관리자가 설정에서 켠 소유자에게만 보낸다. 수신자는 해당 소유자의 Supabase 관리자 로그인 이메일이며 브라우저가 임의 수신자를 지정하지 못한다. 당일 이메일 확보 업체 수가 설정된 목표 이상일 때 SQL에서 하루 한 건만 원자적으로 예약한다. 연결된 Gmail 계정으로 해당 관리자에게 집계 결과와 서비스 링크를 전송한다. 이 알림은 영업 발송·영업 성과 집계와 별개이며, 회사·상품 검증 완료나 영업 메일 발송 완료를 의미하지 않는다.

한 번 제출한 뒤 결과가 불명확하면 중복 방지를 위해 자동 재전송하지 않는다. 실패·접수 미확인은 상태판과 감사 기록에 남긴다. Gmail 서버 접수는 받은편지함 도착을 보장하지 않는다. `202610220005_discovery_notifications.sql` 적용 및 Edge 배포가 필요하고, 소유자 설정의 `notify_completion`은 기본으로 꺼져 있다.
