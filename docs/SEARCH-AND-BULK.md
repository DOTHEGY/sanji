# 검색 보충과 일괄 이메일

자동 발굴은 한국시간 자정의 기업·협회 목록 갱신과 별도로, 대기 후보가 8곳 미만이면 공개 검색어를 보충한다. Google, 네이버, Bing RSS, DuckDuckGo를 순환하며 결과가 비었거나 제한되면 다음 제공자를 확인한다. 계정·유료 API 키는 사용하지 않는다. 보안 확인이나 로그인·차단을 우회하지 않는다. 제공자 HTML 변경이나 데이터센터 차단으로 결과가 없을 수 있으며 하루 40개 업체 확보를 보장하지 않는다.

검색어 2개 단위로 15분 간격, 하루 최대 64개 검색어를 확인한다. 하나의 검색어는 최대 4개 제공자를 시도한다. SQL lease로 중복 실행을 막고, 이메일 확보 목표를 달성하면 보충을 중단한다. 검색 제목은 업체 후보이며 소유 법인이나 식품 분류의 검증 결과가 아니다. 출처·검색어·원본 링크를 비공개 DB에 저장한다. 검색 결과에 적힌 이메일은 자동 채택하지 않고 홈페이지·공식 연결몰에서 다시 확인한다. 회사명·도메인·기존 이메일 중복을 검사한다. 진행 화면에 제공자별 성공·실패와 후보 추가 수를 표시한다.

브랜드 이메일 화면의 `현재 목록 전체 선택` → `선택한 메일 일괄 검토` → 소유 관계 확인·발송 근거 입력 → `최종 발송 내용 확인` → 일괄 승인 → `승인한 메일 지금 일괄 전송`으로 진행한다. 회사 확인 보류 대상은 전체 선택에서 제외한다. 각 회사에는 해당 회사의 허용된 이메일들을 수신자로 묶어 한 통을 보낸다. 개별 체크와 예약 발송도 유지한다. 수신자·내용·첨부를 바꾸면 최종 승인은 무효가 된다. 발송은 승인된 서버 미리보기의 hash로 순차 요청하며 중복·수신 거부·템플릿 버전 검증을 그대로 적용한다. 오류는 건별로 표시하며 자동 재시도하지 않는다.

## 열람 상태

Gmail API의 `messages.send` 성공은 서버 접수이며 받은편지함 도착·읽음이 아니다. Gmail API는 일반 수신자의 열람 여부를 제공하지 않는다. 현재 산지는 Mailsuite와 연동하지 않았으며 Gmail 브라우저 확장 프로그램이 API 발송 메일에도 추적을 넣는다고 가정하지 않는다. Mailsuite에서 별도로 추적한 메일은 해당 제품에서 확인해야 한다. 추적 이미지 요청 이벤트도 보안 스캐너·이미지 프록시·이미지 차단의 영향을 받으므로 사람의 실제 열람으로 확정할 수 없다. 현재 산지는 추적 이미지를 삽입하거나 열람 수치를 생성하지 않는다.

배포 시 `202610220003_search_refill.sql` 적용 후 Edge Function을 업데이트한다. 공개 설치용 SQL은 `public/setup/search-refill.sql`이다. 검색 자체에는 유료 검색·AI 호출이 없지만 Supabase 실행·DB 사용료와 Gmail 계정의 제공자 할당량은 별개다.
