# 브랜드 신규 발굴 자동 예약: 검토 및 반영 계획

별도 소유자별 자동 예약 설정은 기본 꺼짐이다. 설정을 켠 시점부터 최초 이메일을 확보한 신규 후보만 대상으로 하며, 이미 발견한 후보나 기존 예약을 소급 변경하지 않는다. 새 연락처의 확인 시각과 최초 확보 시각 중 늦은 시각을 기준으로 한국시간 월~목은 다음 날 09:00, 금~일은 월요일 09:00으로 예약한다. 처리가 지연되어 예약 시각이 지났으면 즉시 발송하지 않고 다음 평일 09:00을 사용한다.

발굴 실행 후 공식 출처·회사명·수신 거부·영구 반송·본문 검사와 현재 브랜드 템플릿 버전을 확인한다. 회사당 유효 주소 하나만 선택한다. `sanji_brand_auto_commit`은 동일 소유자와 업체에 대한 잠금을 얻고 회사 기록, 초안, 기존 `sanji_schedule_dispatch`를 통한 예약, 자동 예약 연결 기록을 하나의 DB 트랜잭션에서 처리한다. 기존 회사나 연락처·예약이 있으면 새로 예약하지 않는다. 응답 유실이나 재실행은 고유 제약·기존 상태로 중복을 방지한다. 실패는 15분 간격 최대 2회로 제한하며 기존 발송 작업을 재시도하지 않는다. 발송 직전 기존 검증과 제공자 제한 및 실패 처리는 그대로 적용한다.

기존 발굴 자동화가 켜져 있어야 발굴 틱이 신규 예약을 평가한다. 외부 API 사용량이나 목표 70을 이 기능이 변경하지 않는다. 첨부 메타데이터가 있는 템플릿은 첨부 원문을 알 수 없어 자동 예약하지 않는다. 수신 거부·검증 불가·중복·템플릿 불일치 등은 자동 발송하지 않는다. 템플릿 변경 시 기존 예약의 기존 검증 정책은 그대로 적용된다. 실제 청구액은 이 기능으로 확인할 수 없으며 기존 발굴 화면은 유료 검색·AI 호출 집계와 Supabase 청구 미확인을 구분한다.

운영 반영은 백업 후 마이그레이션 `202610280001_brand_auto_schedule.sql`, 함수와 UI 배포 및 수동 확인이 필요하다. 기존 작업을 바꾸지 않으며 새 설정은 기본 꺼짐이다. 실제 활성화는 브랜드 이메일 > 수집 현황·운영 설정 > 신규 검증 브랜드 자동 예약에서 한다. 되돌릴 때는 우선 이 설정을 끄고 함수·UI를 이전 버전으로 되돌린다. 이미 생성된 예약은 자동으로 취소하지 않으므로 목록을 확인해 개별 취소해야 한다. 테이블 삭제는 별도 검토한다. 운영 인증과 실제 스케줄러, 권한, 청구액은 별도 확인 전까지 미검증이다.
