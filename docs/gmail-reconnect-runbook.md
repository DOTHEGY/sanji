# Gmail 인증 복구와 상태 표시

Google 갱신 토큰이 `invalid_grant`를 반환하면 Gmail 연결을 재인증 필요로 표시하고 이후 동기화에서 Google 호출을 반복하지 않는다. 일시 오류는 고정된 안전 메시지만 기록하고 1·2·4·8·16·30분 간격으로 재시도한다. OAuth 연결이 성공하면 동기화 중단 상태를 지우고 다음 틱에서 재개한다. 재연결과 오래된 갱신 응답이 겹칠 때 이전 인증이 새 연결을 덮어쓰지 않도록 암호문 일치 조건으로 갱신한다.

정기 작업 응답은 인증 실패 또는 일시 장애 시 HTTP 503을 반환한다. `pg_cron`이 HTTP 요청을 비동기로 제출하는 구조라면 cron의 SQL 작업 성공은 Google 동기화 성공을 뜻하지 않는다. 앱의 Gmail 연결 상태와 `sanji_gmail_sync.result.status`, 마지막 성공 시각을 확인한다. 토큰과 원문 제공자 응답은 상태에 저장하지 않는다.

연결이 끊긴 동안 자동 브랜드 예약은 새로 만들지 않는다. 이미 기한이 도래해 처리된 예약이 인증 실패하면 기존 실패 처리 규칙을 따르며 자동으로 다시 발송하지 않는다. 계정 재연결 후 예약·발송 상태와 회신 동기화를 확인하고, 실패 건을 재전송하려면 별도로 검토한다. 외부의 권한 취소를 막거나 영구 연결을 보장할 수는 없다.
