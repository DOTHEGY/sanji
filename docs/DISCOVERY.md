# 회사 이메일 발굴

운영 화면의 ‘이메일 자동 발굴’은 하루 공식 회사 이메일 후보 30개를 기본 목표로 합니다.
보장된 결과 수가 아닙니다. 한국시간 날짜별 신규 고유 이메일 후보, 검토 후 등록한 업체,
업체 검토 수를 따로 집계하며 전화번호·문의 폼을 이메일 실적에 넣지 않습니다.

## 발견 → 수집 → 검토 → 메일

‘브랜드 발굴’에 수집 진행 현황과 등록한 브랜드를 통합했습니다. 네이버 API 신청·키 입력 UI는 제거했습니다.
직접 검색·홈페이지 입력은 접힌 보조 기능입니다. 공개 웹 조사는 API 가입 없이 할 수 있지만,
클라우드 작업 환경의 검색 사이트 네트워크 접근은 별도로 허용되어야 합니다. 키가 없다는 이유로
공개 웹 검색 자체가 불가능하다고 안내하지 않습니다.

서버 자동 수집은 운영 DB에 저장한 홈페이지 후보 대기열을 순서대로 처리합니다.
웹 전체를 자동 검색하거나 무한히 신규 회사를 찾는 기능으로 표시하지 않습니다. 대기열이
소진되면 ‘소스 보강 필요’를 표시합니다. 추가한 조사 대상 URL은 검증된 공식 사이트 목록이
아니며 접속·회사 소유 관계·사업 관련성을 확인해야 합니다. 실명 목록은 공개 정적 파일에 넣지 않습니다.

- 홈페이지 푸터의 이메일을 먼저 확인하고, 따옴표 없는 href·패밀리사이트 option으로 연결된 자사몰도 확인합니다. 다른 도메인의 자사몰·기업 오피셜 사이트는 최대 1곳이며 전체 최대 5페이지입니다. 각 도메인의 DNS·IP·리디렉션·robots.txt를 검사합니다. 연결 사실을 동일 법인 소유 증명으로 단정하지 않습니다.
- 실제 공개 이메일을 추출하고 출처·확인일·문맥·용도·푸터 여부·연결 경로를 보관합니다. 대표·일반 문의·고객센터도 포함합니다. HTML 숫자 엔티티와 mailto URL 인코딩도 읽습니다. 사용자 제공 이메일 후보는 별도 표시하며 자동 수집·원문 확인 수에 포함하지 않습니다. 재수집은 기존 사용자 제공 후보를 삭제하지 않습니다.
- 플랫폼 운영사·개인정보·채용·수신불가·입력 예시 주소는 제외합니다. 이메일을 추측하지 않습니다.
- 소유 관계를 직접 승인한 이메일만 브랜드에 등록합니다. 제품 분류·유통 권한은 별도 확인합니다.
- 수집 로그는 업체·확인 시각·페이지 수·메일 수·실패 이유를 보여 주며 화면에서 30초마다 갱신합니다.
  화면 갱신과 서버 작업 주기를 구분하며, 수집 중·대기·대기열 소진·한도 도달을 구분합니다.
- 등록 브랜드에서 저장한 이메일 템플릿을 바로 열 수 있습니다. 일괄 작성에서는 수신자별 개인화,
  제목·공통 본문·서명·첨부를 입력한 뒤 각각의 최종 메일을 확인합니다. 본문 수정은 기존 승인 미리보기를 무효화합니다.
- 수신자별 체크한 최종 미리보기만 기존 `/schedule` API로 순차 예약합니다. 일부 예약 실패는 개별 표시하며
  성공 건을 자동으로 다시 예약하지 않습니다. 단순 미리보기는 발송이나 예약을 수행하지 않습니다.

## 비용과 한도

발굴에 LLM·유료 검색 API는 사용하지 않습니다. 기존 Supabase 프로젝트의 사용량은 발생하며
영구 무료·무제한을 보장하지 않습니다. 하루 최대 160단계, 사이트당 최대 5페이지·페이지당 700KB,
5분 간격으로 한 업체씩 확인합니다. 일일 이메일 목표는 검증 전 후보 수이며 확보 보장이 아닙니다.
차단·보안문자·로그인 제한을 우회하지 않고 실패 이유를 보존합니다.

## 배포와 인증

`supabase/migrations/202610210003_discovery.sql`은 반복 실행 가능하며 RLS로
운영자별 데이터를 보호합니다. 쓰기는 관리자 JWT 또는 비공개 실행기 키 검증 후
서버에서만 처리합니다. 실제 조사 대상·이메일·진행 내역은 운영자 인증 뒤에만 조회합니다.

자동 실행은 `/discovery/tick`에 `x-job-token`을 보내는 별도 Cron입니다.
`DISCOVERY_RUNNER_TOKEN`을 사용하며 메일 `/jobs/run` 실행기와 분리합니다.
Cron 키는 Supabase Vault에서 읽고 SQL 명령에 평문을 넣지 않습니다.

이 기능은 메일 발송·폼 제출·DM 발송을 수행하지 않습니다. 운영 메일은 별도의
최종 수신자·내용 승인, 발신자 정보, 수신 거부·중복·일일 제한 검사를 거칩니다.
첨부는 파일당 2MB, 최대 5개·합계 5MB이며 이미지는 첨부파일입니다. 본문 이미지
삽입은 지원하지 않습니다. Gmail 동기화는 등록 대상의 최근 90일 대화이며 호출당
대상 최대 30명·각 20스레드이고 추가 결과가 있으면 부분 동기화로 표시합니다.

운영 프로젝트에는 별도로 승인한 메일 예약만 실행하는 5분 간격 Cron을 설치할 수 있습니다.
발굴 실행기 키와 메일 실행기 키를 구분하고, 발굴 코드에서는 메일 발송 API를 호출하지 않습니다.

메일 회신은 실제 수신 메시지의 Reply-To(없으면 From) 주소를 사용합니다. 최초 등록
이메일과 다른 경우 최종 미리보기에 확인 안내를 표시하고 해당 주소의 수신 거부도
발송 직전에 검사합니다. 복수·불명확한 회신 주소는 추측하지 않고 원본 확인을 요청합니다.
