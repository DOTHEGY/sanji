# 회사 이메일 발굴

운영 화면의 ‘이메일 자동 발굴’은 하루 공식 회사 이메일 후보 30개를 기본 목표로 합니다.
보장된 결과 수가 아닙니다. 한국시간 날짜별 신규 고유 이메일 후보, 검토 후 등록한 업체,
업체 검토 수를 따로 집계하며 전화번호·문의 폼을 이메일 실적에 넣지 않습니다.

## 발견 → 수집 → 검토

- 네이버 검색 API의 상품검색에서 브랜드·제조사 표기와 상품 원본 링크를 확보합니다.
  쿠팡·스마트스토어 상품도 이 검색 결과에 포함될 수 있습니다. 제조사 표기를 브랜드
  소유 법인으로 단정하지 않습니다. 플랫폼 로그인이나 차단 우회 수집은 제공하지 않습니다.
- 웹문서 검색으로 공식 홈페이지 후보를 찾은 뒤 최대 3개 공개 페이지를 확인합니다.
  DNS·IP와 리디렉션을 검사하고 robots.txt·오류·로그인 제한을 따릅니다.
- 공식 페이지에 실제로 공개된 대표·일반 문의·영업·제휴·고객센터 이메일을 폭넓게
  추출하고 출처·확인일·문맥·용도를 보관합니다. 이메일을 추측하지 않습니다.
- 소유 도메인이 다른 주소는 ‘회사 소유 관계 확인 필요’로 표시합니다. 플랫폼 운영사,
  개인정보·채용·수신불가·입력 예시 주소는 제외합니다. 최종 검증 전 후보입니다.
- 법인과 이메일 소유 관계를 직접 확인한 뒤 브랜드 목록에 등록합니다. 법인·이메일
  중복 등록을 차단하고 제품 법적 분류·유통 권한·딜 조건은 미확인으로 둡니다.
- 공식 URL을 직접 넣으면 검색 키 없이도 이메일 수집이 가능합니다. 미확보 업체는
  이메일 결과 목록에서 기본 숨기며 공식 URL 보완 후 다시 대기열에 넣을 수 있습니다.

## 비용과 한도

발굴에는 LLM 호출이 없습니다. 유료 검색 API나 유료 계정을 자동 신청하지 않습니다.
기존 Supabase 프로젝트와 네이버 검색 API 제공량을 사용하는 구조입니다. 네이버의
현재 제공량·약관은 앱 발급 콘솔에서 확인해야 하며 무제한·영구 무료를 보장하지 않습니다.

하루 최대 160단계, 신규 업체 후보 최대 150곳, 사이트당 HTML 최대 3페이지,
페이지당 최대 700KB로 제한합니다. 5분마다 한 단계만 처리합니다. 이메일 후보 목표 도달,
소스 미연결, 일일 한도 도달 시 작업하지 않습니다. HTTP 실패를 반복 재시도하지 않습니다.
작업 락은 중복 실행을 막고 자동 실행과 직접 실행이 같은 한도를 공유합니다.
키가 없으면 ‘검색 미연결’ 상태이며 하루 30건 자동 발굴이 가동됐다고 표시하지 않습니다.

## 배포와 인증

`supabase/migrations/202610210003_discovery.sql`은 반복 실행 가능하며 RLS로
운영자별 데이터를 보호합니다. 쓰기는 관리자 JWT 또는 비공개 실행기 키 검증 후
서버에서만 처리합니다. 네이버 Client ID·Secret은 운영 화면에서 입력하고 서버에서
암호화 저장합니다. 브라우저 상태·저장소·공개 파일에는 저장하지 않습니다.

자동 실행은 `/discovery/tick`에 `x-job-token`을 보내는 별도 Cron입니다.
`DISCOVERY_RUNNER_TOKEN`을 사용하며 메일 `/jobs/run` 실행기와 분리합니다.
Cron 키는 Supabase Vault에서 읽고 SQL 명령에 평문을 넣지 않습니다.

이 기능은 메일 발송·폼 제출·DM 발송을 수행하지 않습니다. 운영 메일은 별도의
최종 수신자·내용 승인, 발신자 정보, 수신 거부·중복·일일 제한 검사를 거칩니다.
첨부는 파일당 2MB, 최대 5개·합계 5MB이며 이미지는 첨부파일입니다. 본문 이미지
삽입은 지원하지 않습니다. Gmail 동기화는 등록 대상의 최근 90일 대화이며 호출당
대상 최대 30명·각 20스레드이고 추가 결과가 있으면 부분 동기화로 표시합니다.

운영 프로젝트에는 별도로 승인한 메일 예약만 실행하는 5분 간격 Cron을 설치할 수 있습니다.
발굴 실행기 키와 메일 실행기 키를 구분하고, 발굴 코드에서는 메일 발송 API를 호출하지 않습니다.

메일 회신은 실제 수신 메시지의 Reply-To(없으면 From) 주소를 사용합니다. 최초 등록
이메일과 다른 경우 최종 미리보기에 확인 안내를 표시하고 해당 주소의 수신 거부도
발송 직전에 검사합니다. 복수·불명확한 회신 주소는 추측하지 않고 원본 확인을 요청합니다.
